المحور الأول: إطار البحث والدوافع

1. المشكلة الواقعية ودوافع بناء النظام الموزع

المتحدث 1 (00:00 - 01:00)
⚠️ معاناة الواقع الصحي القائم
  • أزمة البحث اليدوي العشوائي: هدر ما بين 45 إلى 120 دقيقة سيراً على الأقدام للبحث عن دواء حرج بين شوارع المدينة.
  • عزلة الأنظمة الصيدلانية: الصيدليات تعمل كجزر معزولة بأنظمة محاسبية محلية مغلقة دون ربط مركزي.
  • ظاهرة الاتصال الكاذب: تأكيد توفر الدواء شفهياً بالهاتف ثم بيعه لمريض آخر قبل وصول العميل.
  • انعدام الشفافية في الأسعار: تباين أسعار نفس الصنف الدوائي بين صيدليات الحي الواحد.
✨ حلول PharmaConnect الهندسية
  • استعلام جغرافي كروي: استكشاف الصيدليات المتوفر لديها الدواء فورياً مع المسافة المحددة بالأمتار.
  • حجز مؤقت عادل (30 دقيقة TTL): حماية حق المريض في الوصول وحق الصيدلي في تصريف الدواء دون تعطيله.
  • حماية المخزون بنسبة 0% أخطاء: منع الـ Race Condition وقفل الصفوف تشاؤمياً.
  • مرونة عالية (Resilience): عمل تطبيق العميل بسلاسة حتى في ظروف انقطاع أو بطء الإنترنت.

2. المعمارية الموزعة ثلاثية الطبقات (3-Tier Architecture)

المتحدث 1 (01:00 - 02:30)
📱 1. Presentation Tier
  • تطبيق الهاتف (Flutter): تجربة لحظية وسريعة للبحث وحجز الدواء.
  • بوابة الصيدلية (Web): واجهة إدارة المخزون وتأكيد الاستلام.
  • أنظمة الكاشير (B2B): ربط مباشر مع نقاط البيع.
  • بروتوكول موحد: Stateless JSON over HTTPS.
⚙️ 2. Logic Tier (Laravel)
  • RESTful API Gateway: توجيه وفحص كافة الطلبات.
  • الأمان بـ Sanctum: مصادقة مشفرة بدون Sessions.
  • محركات الخدمات: GeoSearchService و ReservationService.
  • Repository Pattern: عزل الاستعلامات عن المنطق.
🗄️ 3. Data Tier (DB)
  • قاعدة بيانات 3NF: تفادي التكرار وضمان التماسك.
  • المعاملات الذرية (ACID): تنفيذ العمليات بأمان تام.
  • قفل الصفوف: InnoDB Row-Level Locking.
  • تكامل مرجعي: قيود المفاتيح الأجنبية الصارمة.
المحور الثالث: هندسة البيانات وتكامل النظم

3. هندسة البيانات والشكل المعياري الثالث (3NF Database)

المتحدث 1 (02:30 - 04:00)
📋 الجداول الـ 7 الرئيسية في النظام
  • users: إدارة هويات المرضى ومدراء الصيدليات والمشرفين (RBAC).
  • pharmacies: بيانات الصيدلية، الهاتف، والإحداثيات الجغرافية (lat, lng).
  • medicines: السجل القومي الموحد (الاسم التجاري والعلمي والعيار).
  • pharmacy_medicines: وسيط الربط وإدارة المخزون والسعر لكل صيدلية.
  • reservations & items: تذاكر الحجز والمهلة والأصناف والأسعار.
💡 مبررات التصميم أمام اللجنة الأكاديمية
  • انعدام التكرار (Zero Redundancy): معلومات الدواء تسجل مرة واحدة عالمياً ويربط بها مخزون كل صيدلية.
  • استقلالية التسعير: كل صيدلية تملك كامل الحرية بتحديد كمياتها وأسعارها.
  • دورة حياة الحجز الخماسية: pending ➔ confirmed ➔ completed / cancelled / expired.
  • التكامل المرجعي: منع الحجوزات الوهمية أو العمليات غير المعرفة.

4. حل معضلة التزامن والرياضيات الكروية (Concurrency & Math)

المتحدث 1 (04:00 - 05:30)
🔒 منع الـ Race Condition بالقفل التشاؤمي

حماية المخزون من الحجز المزدوج إذا طلب مريضان آخر علبة في نفس الجزء من الثانية:

// ReservationService.php DB::transaction(function () use ($stockId, $qty) { $stock = PharmacyMedicine::where('id', $stockId) ->lockForUpdate() // قفل الصف الحصري ->first(); if ($stock->available_quantity < $qty) { throw new Exception('الكمية لم تعد متوفرة'); } $stock->decrement('available_quantity', $qty); });
🌍 خوارزمية هافرسين الكروية (Haversine)
  • لماذا هافرسين؟ المسافة الإقليدية تفترض تسطح الأرض وتولد أخطاء فادحة، بينما هافرسين تحسب البعد على سطح كروي مع اعتبار نصف قطر الأرض (R = 6371 km).
  • ترتيب النتائج: حساب المسافة بالكيلومتر وترتيب الصيدليات من الأقرب فورياً للمريض.
  • استقلالية تامة: حساب رياضي داخلي دون تكلفة أو مفاتيح API مدفوعة.
