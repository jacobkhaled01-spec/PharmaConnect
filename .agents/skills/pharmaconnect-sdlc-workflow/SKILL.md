# مهارة قيادة دورة حياة تطوير النظام (PharmaConnect SDLC Workflow)

توفر هذه المهارة إجراءات تفصيلية لتنفيذ كل مرحلة من مراحل تطوير نظام **فارما-كونكت (PharmaConnect)** وفق أرقى المعايير الهندسية والبرمجية.

## 1. إجراءات مرحلة التحليل (Analysis Phase)
عند العمل على متطلبات النظام:
1. تصنيف المتطلبات إلى:
   - **متطلبات وظيفية (Functional):**
     - تسجيل الصيدليات وتوثيق رخصها.
     - إدارة المخزون وتحديد التوفر والأسعار.
     - البحث متعدد المعايير وتحديد أقرب الصيدليات جغرافياً.
     - الحجز المؤقت وتأكيد الاستلام.
   - **متطلبات غير وظيفية (Non-Functional):** الأمان، سرعة الاستجابة، التزامن، والاعتمادية.
2. بناء مصفوفة تتبع المتطلبات (Traceability Matrix).

---

## 2. إجراءات مرحلة التصميم (Design & Modeling Phase)
عند تصميم المخططات المعمارية:
1. **مخططات UML:**
   - رسم المخططات بصيغة Mermaid المعيارية.
   - مخطط حالات الاستخدام (Use Case Diagram) لكل فاعل (صيدلي، مريض، مدير).
   - مخطط التتابع (Sequence Diagram) لمسار البحث والحجز.
   - مخطط الفئات (Class Diagram) موضحاً فئات Laravel و Flutter والعلاقات كائنية التوجه.
2. **تصميم قاعدة البيانات (ERD):**
   - تصميم الجداول الأساسية:
     - `users`: بيانات المشتركين وأدوارهم (Role-Based Access Control).
     - `pharmacies`: بيانات الصيدلية، الموقع الجغرافي (Latitude, Longitude)، وأوقات العمل.
     - `medicines`: الفهرس العام للأدوية (الاسم العلمي، التجاري، الباركود، التصنيف).
     - `pharmacy_medicines` (المخزون): الكمية المتوفرة، السعر، حالة التوفر.
     - `reservations`: الحجوزات المؤقتة، وقت الإنشاء، وقت الانتهاء (TTL)، وحالة الحجز.

---

## 3. إجراءات مرحلة التنفيذ (Implementation Phase)
1. **الخادم المركزي (Laravel Backend):**
   - استخدام الـ Migrations و Seeders لبناء قاعدة البيانات.
   - تطبيق نمط Repository & Service Pattern.
   - توفير مسارات الويب لشاشات إدارة المخزون (Blade/Tailwind أو Vue.js).
   - توفير مسارات الـ API المحمية بـ Sanctum لتطبيق الموبايل.
2. **عميل الهاتف (Flutter Client):**
   - فصل طبقة الـ Data والـ Domain والـ Presentation.
   - تطبيق لوحة الألوان الطبية (Green & White Theme).
   - استخدام إدارة الحالة المعتمدة (Provider / Bloc).

---

## 4. إجراءات الاختبار وضمان الجودة (QA & Testing Phase)
1. كتابة اختبارات الـ Feature والاختبارات التلقائية لمسارات الـ APIs الحساسة:
   - التحقق من رفض الحجز في حال كانت الكمية 0.
   - التحقق من إلغاء الحجز تلقائياً بعد مرور وقت الـ TTL.
2. توثيق واجهات Postman وتصدير ملف التوثيق للمطورين.
