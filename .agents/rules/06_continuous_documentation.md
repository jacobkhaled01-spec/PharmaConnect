# بروتوكول التوثيق اللحظي بعد كل خطوة (Continuous Step-by-Step Documentation)

تُلزم هذه القاعدة الوكيل البرمجي والفريق بتطبيق سياسة **التوثيق اللحظي الصارم (Atomic Documentation)**، بحيث لا يُعتبر أي إجراء أو مهمة مكتملاً ما لم يتم توثيقه وتحديث سجلاته في نفس اللحظة.

## 1. قواعد التوثيق بعد كل خطوة:
1. **تحديث سجل التغييرات (`CHANGELOG.md`):**
   - بعد أي إنشاء لملف، تعديل في الكود، إضافة ميزة، أو إصلاح خطأ، يجب فتح ملف [`CHANGELOG.md`](file:///d:/IT%20FILES/level%204/خادم%20وعميل/مشروع%20الصيدلية/CHANGELOG.md) وتدوين التغيير مباشرة تحت الإصدار النشط مصنفاً حسب النمط المعياري (Added, Changed, Fixed, Removed, Security).
2. **تحديث ذاكرة المشروع والمخططات:**
   - عند استحداث جدول في قاعدة البيانات، أو مسار API جديد، يتم تحديث وثيقة المعمارية في مجلد `/docs` فوراً.
3. **توثيق رسائل الـ Commit:**
   - يجب أن تعكس كل عملية حفظ على Git التغييرات التي تمت بدقة متناهية وفق معايير Conventional Commits.
4. **توثيق الأكواد المصدرية (In-Code Documentation):**
   - كتابة تعليقات توضيحية موحدة (PHPDoc في Laravel و DartDoc في Flutter) على كافة الدوال والفئات والواجهات توضح المدخلات (Parameters)، المخرجات (Returns)، والاستثناءات المحتملة (Exceptions).

## 2. جدول التحقق من إغلاق التوثيق:
| الخطوة المنفذة | الإجراء التوثيقي المطلوب فوراً |
|---|---|
| إنشاء / تعديل ملف برمجي | توثيق الدوال والمتحكم في الكود + تسجيل العملية في `CHANGELOG.md`. |
| تعديل بنيوي أو معماري | تحديث ملفات التصميم في `/docs` + تحديث `walkthrough.md`. |
| تنفيذ Commit في Git | كتابة رسالة معيّارية وتحديث رقم الإصدار وتاريخ التعديل في السجل. |
